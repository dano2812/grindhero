# Security reporting

Do not post exploitable vulnerabilities, credentials, purchase tokens, or personal
data in public issues. If this repository offers GitHub private vulnerability
reporting, use its Security tab. Otherwise, contact the repository owner privately
and agree on a secure channel before sharing sensitive evidence.

Private reporting must be enabled and a monitored contact published before an
external beta. No response-time commitment or supported release window is
established yet. Never send a real customer's receipt or save to demonstrate a bug;
use sanitized sandbox data.

Implementation requirements and the pre-purchase security gate are documented in
[security](docs/security.md).
